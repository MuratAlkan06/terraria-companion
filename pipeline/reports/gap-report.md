- **no-known-route**: an input item has no recipe or drop in the datasets (base materials, vendor/fishing/chest-only items: item corpus P6-S0)
- **drop-source-ungated**: a drop comes from an enemy, an event boss or a container whose own gating is not verified (Enemy.stage Unknown; event bosses are progression markers, not Boss records; containers carry no gating data)
- **boss-attribution-pending**: a boss drop has no verified boss → progression-node attribution (source.bossId Unknown: the row's NPC ids disagree with the registry boss)
- **drop-conditions-unknown**: a drop lists its conditions as Unknown
- **vendor-conditions-unknown**: a purchase route exists but the shop availability conditions are not structured on the wiki
- **progression-graph-pending**: a gate maps to a progression node that is not in the dataset, so the stage cannot be computed
- **acquisition-withheld**: the item's acquisition is withheld because wiki sources conflict (AMENDMENTS-004 B19)
- **alternative-route-unverified**: one route is derivable, but another route is not, and it could be the less gated one — the minimum over routes is unknown (§7b)
- **cycle**: every route needs the item itself (recipe cycle)

- **#2 recipe-group encoding** — Cargo Recipes stores a group ingredient as its plain English name ("¦Any Iron Bar¦" in `ingredients`, "Any Iron Bar¦2" in `args`, "¦Any Iron Bar¦2" in `ings`); members are not in Cargo. Members come from Module:Recipes `group("Any …", {names})` (what the {{recipes}} template uses), resolved to IDs via Module:Iteminfo/data and cross-checked against Module:RecipeGroups (the game's SetupRecipeGroups, v1.4.5.4 transcription). Station alternatives (B3) come from Module:Recipes/l10n `en.station_cate` ("Iron Anvil" → "Iron or Lead Anvil").
- **#3 drop NPC ids / multi-part bosses** — Cargo Drops `id` carries NPC ids for most NPC rows (single, comma lists, ranges, per-variant notes, negative variant netIDs); container rows (crates, chests, treasure bags) carry none or the boss id. Ids are cross-checked against Cargo NPCs by name (mismatches withheld + gap); empty ids are filled from NPCs. Multi-part bosses: every part/segment NPC is typed `boss Part` and lives on the boss article (`_page`), so drops attribute to that boss. P2-S6: the boss registry resolves each boss-typed / treasure-bag row by its article (bossId, cross-checked against the boss's NPC ids); rows on event-boss articles get no bossId (not applicable — events are markers, A3).
- **#8 Imageinfo → sprite file resolution** — Cargo Items `imagefile` names the infobox image ("Zenith.png"); `prop=imageinfo&iiprop=url|size|sha1|mime` on "File:<imagefile>" (50 titles per request) returns the original file URL on terraria.wiki.gg/images/, its SHA-1, size and dimensions; the URL's ?<6 hex> key is the SHA-1 prefix (pins the file version). The wiki's CDN (Cloudflare Polish, `cf-polished: ok, orig_size=N`) serves most PNGs re-encoded, so a byte-exact SHA-1 match is only possible for some files; downloads are accepted when the SHA-1 matches exactly OR the CDN-reported original size equals the wiki's recorded size of that version (pipeline:sprites reports both counts).
- **#13 Cargo paging** — limit=5000 requested; the server returned at most 500 rows per page for every table (Recipes 9 pages, Drops 7, NPCs 2, Items 13, Weapon_source 3). Pagination is by offset ordered by _ID until COUNT(*) is reached.
