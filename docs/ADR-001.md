## D1. Game version pin

Pin the entire site to **Terraria 1.4.5.8 (Desktop, 2026-08-23)** — VERIFIED. Version string lives in one place (`src/data/meta.json`, emitted by the pipeline), displayed in footer and on every data-driven page.

**Caveat.** `Module:Iteminfo` data is synced to 1.4.5.7. Pipeline records the wiki revision ID of the consumed data module; items changed in the 1.4.5.7→1.4.5.8 patch diff are spot-checked; affected fields marked `verified:false` until confirmed.

## D2. Data pipeline (most critical)

Build-time **Node/TypeScript scripts (`pipeline/`, run via `tsx`)** emitting **versioned, validated JSON committed to the repo**. The client ships only baked JSON; it never contacts the wiki at runtime.

Extraction sources, priority order per field:
1. **`Module:Iteminfo/data`** (raw Lua via revisions API, parsed with `luaparse`) — canonical source for numeric stats and **stable integer item IDs** (our canonical record IDs).
2. **Cargo tables via `action=cargoquery`**: Items, Recipes, Drops, NPCs, Equipinfo, Weapon_source, Exclusive, Imageinfo. ~40–60 HTTP requests for a full sync.
3. **Images:** resolved via Imageinfo, downloaded once to `public/sprites/<type>/<id>.png` with a manifest recording each file's wiki source URL.
4. **Curated overlay files** (hand-authored, schema-validated, each entry carrying a wiki source URL): boss progression graph, boss strategies, set bonuses, Weapon Lab archetype parameters. Editorial content is first-class, provenance-tracked input — never invented data.

Stages: fetch → raw cache (gitignored) → parse → merge (Iteminfo wins numeric conflicts) → cross-check (Cargo vs Iteminfo; mismatch ⇒ `verified:false` + entry in generated `gaps.json`) → validate (Zod schemas shared with the app) → emit `src/data/*.json` + `meta.json`. Missing/unverified fields render as "Unknown" per REQUIREMENTS §13.

**Provenance format (per record):**
```json
{
  "id": 4956,
  "_prov": {
    "gameVersion": "1.4.5.8",
    "sources": [
      { "kind": "iteminfo", "url": "https://terraria.wiki.gg/wiki/Module:Iteminfo/data", "rev": 123456, "fetchedAt": "2026-10-12" },
      { "kind": "cargo:Items", "url": "https://terraria.wiki.gg/wiki/Zenith", "fetchedAt": "2026-10-12" }
    ],
    "verified": true,
    "unverifiedFields": []
  }
}
```
Dataset-level `meta.json`: gameVersion, generatedAt, per-table counts, license notice, gap summary.

**Etiquette (rate policy UNVERIFIED — conservative defaults):** serial requests ≤1 req/sec, `maxlag=5`, descriptive User-Agent pointing at the project repo, aggressive local caching (full resync only on game/wiki version change), backoff on 429/5xx, full compliance if wiki.gg objects; fallback = manual Special:Export of the data module.

**Rejected:** runtime client→wiki calls (unpinnable, violates no-runtime-scraping); XML dumps (availability UNVERIFIED); HTML scraping (brittle); third-party npm datasets (stale, unverifiable — fails §13).

## D3. Licensing and compliance

Comply with **CC BY-NC-SA 4.0** (VERIFIED — 4.0, not 3.0) for wiki-derived text/data; sprites are Re-Logic IP handled separately.
- **Non-commercial:** free forever — no ads, no monetization, no affiliate links. Binding.
- **Attribution:** persistent footer ("Data from the Official Terraria Wiki, CC BY-NC-SA 4.0 — Terraria content © Re-Logic") + `/about/licensing` page; every detail page links its wiki source URL.
- **Share-alike:** `src/data/` datasets published under CC BY-NC-SA 4.0 with their own LICENSE; application code independently licensed (MIT).
- **Sprites:** wiki image files are NOT CC-licensed (Re-Logic copyright). No formal fan-site grant exists (UNVERIFIED permission — residual risk, flagged). Plan: download at build time (never hotlink), per-file source URL + rights note in sprite manifest, prominent Re-Logic attribution, takedown contact, and a prebuilt fallback mode swapping item sprites for original pixel-art placeholders via one asset-resolver flag. Decorative/brand art (homepage background, UI chrome) is **original pixel art** from day one.

_As built (AMENDMENTS-016 B127, B130; recorded by the release closeout B132):_
- **Data license — letter met:** `src/data/LICENSE.md` is the datasets' own license pointer (CC BY-NC-SA 4.0, attribution, links to `LICENSES/DATA-NOTICE.md` and `LICENSES/CC-BY-NC-SA-4.0.txt`; `meta.ts` named as not covered). It is not a pipeline output — the emit stage leaves it in place and `pipeline/emit/write.test.ts` pins that, so a rebuild never deletes it (B130). Root `NOTICE` + `LICENSES/{CC-BY-NC-SA-4.0.txt, OFL-1.1.txt, DATA-NOTICE.md}` carry the full terms (B127).
- **Code license — granted — MIT (deploy-prep commit; LICENSE at repo root):** "MIT code" above is the plan, but a license grant is the owner's personal decision (B127, owner input 2). Until the owner confirms MIT (or picks another), there is no `LICENSE` file and `NOTICE` says the source is not offered under any license; a test flips NOTICE's line when a `LICENSE*` file appears.
- **Shipped libraries:** `vite build` writes the bundled packages' license texts to `dist/licenses/third-party-software.txt` (`build.license`; dist-only — a dev 404 is accepted; indirect packages without a LICENSE file are named, not texted — B130). The Licensing page links it.
- **Attribution + takedown:** `/about/licensing` (six sections — UX_SPEC §1); the takedown flip point and runbook are README's "Takedown runbook (sprites)" (B112(b), B127); the takedown contact is set: the repo’s GitHub Issues page (deploy-prep commit; swappable per README) (B127, owner input 1).

## D4. Frontend stack

**Vite 8** (`react-ts` template: React 19.2, TS ~6.0, plugin-react 6 — VERIFIED current), SPA mode.
- **Routing:** React Router v7 (library mode) with `React.lazy` route chunks. (Next.js rejected: no server features needed.)
- **Styling:** Tailwind CSS v4 over CSS custom-property design tokens (forest green/deep blue/earth brown/stone gray/warm gold), dark-only; `image-rendering: pixelated` utilities; custom kit (ItemSlot, InventoryGrid, TerrariaTooltip, PixelPanel). Fonts: Press Start 2P (OFL) accents, Inter (OFL) body. Radix UI primitives only where a11y is hard (tooltip, dialog, combobox).
- **State:** Zustand v5 for cross-cutting state (progression, owned items, saved builds, settings); component state elsewhere. No Redux, no React Query.
- **Search:** MiniSearch — one lazy-initialized index over compact docs (id, name, type, class, stage, tags) for all ~6.4k entities; `autoSuggest` + `search` with `prefix: true, fuzzy: 0.2`, name boosting, facet `filter`. Runtime-built on first search; `toJSON`/`loadJSON` prebuilt index is the escape hatch (deferred).

## D5. Weapon Lab rendering

**Two strictly separated layers.**
1. **Simulation core:** hand-rolled pure TypeScript, fixed-timestep 60 Hz accumulator loop, seeded deterministic RNG (mulberry32). No PixiJS imports in the sim. Same seed + loadout + duration ⇒ bit-identical totals at any frame rate — headless-testable in Node (CI runs 10s/30s standardized tests and asserts invariance). Weapon behaviors = **archetypes** parameterized per weapon from D2 data; unsupported mechanics render an explicit limitation label per §2.
2. **Render layer:** PixiJS v8 (8.21 VERIFIED), lazy-loaded only on the Lab route. `TextureStyle.defaultOptions.scaleMode = 'nearest'` + `roundPixels`; spritesheet atlas for arena/dummies/projectiles; `BitmapText` pools for floating damage numbers; renderer interpolates between sim ticks.

(Rejected: hand-rolled Canvas 2D — rebuilds batching/atlases/text pooling for no benefit; Phaser — full engine, speculative complexity; raw WebGL — unjustifiable.)

## D6. Persistence

**localStorage only**, behind a storage module (`loadDomain/saveDomain`) so the engine is swappable. Namespaced keys: `tc.v1.builds`, `tc.v1.favorites`, `tc.v1.progress`, `tc.v1.plans`, `tc.v1.recent`, `tc.v1.settings`. Versioned envelopes `{ v, savedAt, gameVersion, data }`; migration registry of pure functions runs on read; corrupt payloads **quarantined** under `tc.quarantine.*` with a visible notice — never silently wiped. Records reference stable game item IDs (D1/D2), so dataset refreshes don't orphan builds.
_As built (key list; recorded by the release closeout B132):_ eight domains (`DOMAIN_KEYS`, src/storage/index.ts) — the six above, with `tc.v1.progress` registered as planned (ratified AMENDMENTS-014 B74(d)), plus `tc.v1.checklists` (AMENDMENTS-001 A7: boss-page and guide checklists) and `tc.v1.readiness` (Feature A AC4; DATA_SCHEMA_SPEC §4b). `tc.retryFocus` is a session-only note, not a domain — never backed up, restored or quarantined (UX_SPEC §5.4, AMENDMENTS-016 B128).

**Export/import:** readable text block — human-skimmable header (stage/class/difficulty, item names) + `#code:` line of base64url canonical JSON; import parses the code line ~~, falls back to name resolution with explicit "unknown item" errors~~. _(Name-resolution fallback RETIRED — AMENDMENTS-016 B124: code-only by design; see "As built" below.)_

_As built (AMENDMENTS-016 B123, B124; P7-S2 + P7-S2b):_
- **Whole-data backup (P7-S2, B123(a)/(b)/(e)/(f)):** one JSON file `{ format: "terraria-companion-backup", v: 1, exportedAt, app, appVersion, gameVersion, domains: { <domain>: <this ADR's envelope> } }` (DATA_SCHEMA_SPEC §8d). Every part is read with the load path's decoder (version check, migrations, strict parse), so an import passes exactly when a load would; per part merge / replace / skip (local wins on conflict); an unreadable part is set aside under `tc.quarantine.*`, never dropped.
- **One build as text (P7-S2b, B123(a)):** the readable block (name, class, stage, difficulty, goal, target boss; export date with the app and game-data versions; the slots in plain words, emptied-by-you told apart from left-empty-by-the-recommendation; owned gear) ends in ONE line `#code: tcb.<v>.<payload>.<check>` — `v` the saved-build version (2), `payload` base64url of the canonical JSON (keys sorted, no spaces) of `{ build: <SavedBuild minus buildId/createdAt/updatedAt>, gameVersion }`, `check` an FNV-1a-32 over `tcb.<v>.<payload>` so a cut-short or edited code is refused as damaged rather than read as another build. Deterministic. Import reads the code line (or a bare code) only, through the same load path; refusals are honest (not a build code / several codes / damaged / newer version / fails the checks). Item ids the data doesn't know are kept, listed by id and counted. An import is saved as a NEW build. **Retired (AMENDMENTS-016 B124), closed:** the name-resolution fallback above — the `#code:` line is the machine contract and the readable block is for humans, never parsed; parsing prose lines invites silent misreads, the opposite of the damage-refusal guarantee. Code-only by design.

(IndexedDB deferred behind the storage interface; trigger: blobs or >1 MB persisted.)

## D7. Performance strategy and budgets

- **Data:** per-entity-type JSON chunks, list/search-critical fields separated from heavy detail fields; lazy-loaded per route via dynamic import (Vite code-splits/content-hashes). Shard a chunk only when it exceeds budget.
- **Search:** lazily built once from shipped compact docs; Web Worker and/or prebuilt index only if the 500 ms budget breaks.
- **Images:** small individual PNGs, `loading="lazy"`, inside virtualized lists (~30 live rows); packed atlases ONLY in the Weapon Lab. No global atlas.
- **Budgets (CI-checked):** initial route JS ≤ 200 KB gz; CSS ≤ 30 KB gz; any data chunk ≤ 300 KB gz; Weapon Lab lazy chunk (incl. PixiJS) ≤ 500 KB gz; search init ≤ 500 ms mid-range mobile; LCP ≤ 2.5 s throttled 4G; Lab 60 fps with ≥500 live entities, sim tick ≤ 4 ms.

## D8. Deployment shape

**Pure static site** — `vite build` → `dist/`, zero servers, zero secrets (MediaWiki API is anonymous; pipeline needs no key). Primary host: Cloudflare Pages (SPA fallback `_redirects: /* /index.html 200`); GitHub Pages alternate (404.html fallback). CI (GitHub Actions): typecheck, tests (headless sim determinism, migrations, pipeline schema validation), budget checks, deploy. **No AI-attribution trailers** anywhere in commits/PRs/tags/releases (owner ruling).

**Static feasibility confirmed feature-by-feature:** search, databases, crafting trees, Weapon Lab, Loadout Builder, comparison, Boss Readiness, Acquisition Planner, all tracking/persistence — no requirement needs a server.

## Deferred (with revisit triggers)

IndexedDB (>1 MB or blobs); prebuilt search index / worker (>500 ms init); global sprite atlases; PWA/offline; i18n; URL-shareable builds; per-item prose extraction; any backend. Triggers: wiki objection or schema drift → rerun/re-freeze; sprite takedown → flip asset flag; chunk >300 KB gz or jank → shard/worker; sim tick >4 ms → pooling/culling; persisted >1 MB → IndexedDB; multi-device sync demanded → new ADR.

## Corrections to prior assumptions (for the record)

1. License is CC BY-NC-SA **4.0**, not 3.0.
2. The wiki offers BOTH Cargo tables and game-source Lua data (`Module:Iteminfo/data`) — pipeline merges them, Iteminfo as numeric ground truth.
3. robots.txt nominally disallows `/api.php`; treated as a crawler directive per MediaWiki convention but flagged honestly, with etiquette mitigations and a documented fallback.
4. `Module:Iteminfo/data` synced to 1.4.5.7 vs pinned 1.4.5.8 — record module revision, spot-check patch diff.
